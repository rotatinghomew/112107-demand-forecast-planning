# 社区居家服务需求预测与可承接计划

以下资料为合成记录，不含实际个人信息。文件以 UTF-8 编码，普通字段含日期或本地时间（东八区），分号表示同一字段的多值。空值表示在该记录中未提供，不自动当零。表内的凭据编号用于核对记录归属。

## 数据来源

- `data/accounts.csv`：家庭的真实服务承诺与时点不同的改变；frequency 是每周次数，minutes 是每次派班计入分钟。
- `data/shift_calendar.csv`：较早确认的固定班和数量可变的替代班，均按周一开始的一周记录，分钟为整周。
- `data/flex_agreements.csv`：已签可复用及条件约；临时班计划的替代班只对列出的适用周有效。
- `data/offers.csv`：承诺起始周、完整持续周期与采购。
- `data/planning_policy.csv`：计划验算需要的参数；区间覆盖和续约风险限额不是固定算法。
- `data/past_events.csv`：较早团组的逐项历史回执，末期有右删失。同一生效日可先收到到期、若干天后才收到续约结论。
- `data/history_cutoffs.csv`：各站采集覆盖止日为已可核观察长度，不是所有家庭结束日。

## 环境及检查

使用 Python 3.11.2 标准库，无需网络或额外安装。在项目目录可执行 `python3 -m unittest discover -s tests -v` 核对输入文件、表头与记录形状。各来源字段及记录数量见 `data-contract.json`。

## 计划系统（src/careplan）

在数据读取检查之上，提供一套把凭据事件溯源成逐周占用、并据此审批新一期服务的工具。所有代码仅用标准库；建议以隔离模式运行，避免工作目录中的同名模块被导入：

```
python3 -I careplan_cli.py <子命令> ...
```

### 模块与职责

- `timeutils`：周一锚定的业务周历（周中生效事件归入所在周，释放在下一周生效）。
- `sources`：CSV 读取、表头/形状校验、空值不当零、日期与数字显式转换。
- `timeline`：逐户凭据重放成逐周状态机——`active`（上门占用）/`paused`（临时离家、无上门但保留原班与回归权）/`closed`（可腾退）。只重放 `known_at <= 截点` 的凭据；右删失保持原态，绝不转成结项。
- `capacity`：站点班次表、固定班与替代班、跨周采购；硬余额只承认确定腾退与已签确定替代班。
- `history`：按开始批次（团组）估计续约率（Wilson 区间）与强退周风险率（Poisson 区间），两类结项分开建模、不合并比例；团组数、最短观察周数、滚动区间覆盖率任一不满足则该站点×频率组合标记为不可校验。
- `backtest`：只用当时已知凭据的滚动截点回验，输出未来各周劳时区间并核对覆盖率；目标周超出观察止日记为不可校验而非失败，真值只核对截点已开始的在户团组。
- `planning`：整段服务期逐周可承诺余额、风险冻结、采购限额与替代班约束；家庭提前回来时先核原权益再判整体转移，禁止静默取消一周；并把资源损失归因到续约偏差、家庭实际恢复、替代班未兑现三类。
- `registry`：审批、复用/替代、回看记录的只追加登记簿，同一项目反复审订保留全部版本，已批准占用结转到下一次计划。
- `cli`：命令行入口。

### 命令

```
# 某知情截点下的逐周台账（占用/保留/可腾退/待续约）
python3 -I careplan_cli.py ledger --data data --as-of 2026-05-15 --through 2026-06-08

# 历史团组的删失感知估计与组合可校验性（自动接入回验覆盖率）
python3 -I careplan_cli.py history --data data --station 山前

# 滚动截点区间覆盖率回验
python3 -I careplan_cli.py backtest --data data

# 审订新一期（整周期校验；带 --registry 时登记并结转跨周占用）
python3 -I careplan_cli.py approve --data data --as-of 2026-05-15 \
    --ref N1 --from 2026-05-18 --weeks 3 --frequency 2 --minutes 60 \
    --registry registry/plan.json

# 家庭提前回来：核定原权益并判断临时方案能否整体转到替代班
python3 -I careplan_cli.py return --data data --as-of 2026-05-22 --case H1 --week 2026-05-25

# 回看兑现并归因资源损失
python3 -I careplan_cli.py review --data data --as-of 2026-06-08 --registry registry/plan.json
```

### 关键业务纪律（由测试固化）

1. 暂停家庭当周无上门回执，但保留原班与优先回归权，其分钟不可腾退、不可凭预测外借。
2. 通知时间晚于计划截点的凭据不提前使用；待续约未给结论既不是明示续约也不是释放。
3. 右删失不等于结项；强退结项与到期不续约走不同风险模型，不共用一个比例。
4. 站点×频率组合团组数/观察周数/区间覆盖率不达标即不可校验，预测不得替代个别承诺占班。
5. 新一期必须整段服务期每周放得下；借用保留班必须有确定替代班；采购受费用上限与未备基金风险比例约束。
6. 已批准的跨周占用结转进下一次计划；提前回来先核权益再整体转移，禁止为凑总工时静默取消一周。

`tests/` 下 29 个用例覆盖上述纪律，可用 `python3 -I -m unittest discover -s tests -v` 运行。`registry/` 下的登记簿为运行产物，已在 `.gitignore` 中忽略。
